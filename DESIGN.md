# Context care design and evidence

## Implementation and ownership

The independent ESM Cordis package owns context maintenance, complete request budgets, request-only reminders, completed-output feedback and completion-wording observation. It obtains capabilities through public injected services and events; runtime source has no Harness imports or checkout discovery. Harness source, agent-loop and compaction-basic remain unchanged.

The `/runtime` Host entry installs tools and the numeric Session projection across sessions. The package root is a browser-only display companion; disabling it does not remove tools, sampling, maintenance or HTTP queries. The `/agent` entry contributes equivalent per-scope maintenance. The visible `context_rest` tool identifies the owner: a scoped tool shadows the root implementation, preventing duplicate sampling, notifications or compaction. The Host resolves the compaction provider through `agentPresets.serviceFor(agent, 'compaction')`, then the optional Host service. Shared `/requests` and `/completion` entries own their storage domains independently from the agent contribution. Preset-owned compaction consumers belong inside the same isolated compaction group as their provider.

The Host uses the actual webServer service for `/context-care/rewrite-journal`. This endpoint reads the existing rewrite journal, applies optional connection rejection and removes its route on unload. Numeric status uses the session-scoped `contextCareNumeric` projection; the client contains no alternate token estimator. Request and maintenance audit records are exposed through `contextCareRequests.list/flush`; the rewrite card is not a general request-budget action panel.

## Complete input pricing

Fatigue estimates the next complete input; wakefulness measures retained input-priced history. Output billing does not enter the next input budget. Public token-meter estimates supply text, message framing and schema contributions. Known image projection prices contribute independent visual tokens; file request handles are captured once for the operation. Fixed heuristic shadows remain separate from routed input prices.

Ready persists complete raw text and visual prices, effective config/tools identity, actual route, input fingerprint and dispatch/settlement facts. Matching successful dispatched conversation samples calibrate text by `(input + cacheRead + cacheWrite - capturedVisual) / rawText`. The denominator includes request-only system text, reminders and tools. Failed, interrupted, auxiliary, mismatched and below-raw samples do not calibrate. Valid large multipliers remain valid. Requests without an eligible matching sample use scale 1; legacy request-plus-response pressure never supplies input calibration. Legacy `providerUsageRatio` does not filter new decisions.

Before freezing a maintenance basis, pre-step awaits the previous request journal settlement ACK. Pruning, summary replacement and deep-rest validation remeasure under that frozen text scale and attachment projection. Changes in later usage or adapter pricing affect the next operation. Final ready uses the dispatch-bound image pricing, including explicit absence. The public image-pricing interface has no durable generation identifier, so the plugin does not claim generation-aware sample eligibility or exact tokenizer counting. Planning observes currently available projections; final admission binds the actual projected request.

## Budget policy

`C` is the minimum of known adapter capacity and explicit policy capacity. Unknown capacity is not guessed from a model name. `R` comes from this call's explicit output cap, adapter default or absent. Hard input is `H=min(C-R-safetyTokens, billingInputCeilingTokens-safetyTokens)` when a billing ceiling exists. Soft input is `S=min(floor(budgetRatio*C), H-burstTokens)`; the active maintenance target is `L=S-releaseMarginTokens`. Tail retention derives from `C-R`, with an optional absolute `retainTokens`, including zero. Invalid resolved budgets fail at the earliest available capacity.

Exact provider/model/purpose `routeBudgets` override global capacity and billing policy. Safety, burst and release migration defaults are zero; deployments should choose explicit allowances. Legacy soft/hard/hysteresis/auxiliary ratios remain accepted and validated but do not select the new complete-input thresholds. Summary uses its own route capacity, output reservation, optional summary safety and billing ceiling. Its complete fixed system/tools/applicable prompts/directive cost consumes that budget before range material is added; it does not use the old auxiliary ratio.

Notice-channel, rule and loop messages are collected before ordinary maintenance. Predicted state-message and request-only prompt costs enter planning. This is a forecast; ready checks the complete actual input and persists its facts before returning `REQUEST_BUDGET_EXCEEDED`. A local refusal prevents adapter dispatch. The stable terminal stream stores error code and message; detailed origin and budgetKind remain runtime/journal facts.

## Maintenance and summary transactions

Each Session has independent maintenance hysteresis. At a safe pre-step boundary, the controller prunes available tool results, waits for completion, remeasures and selects a complete prefix while retaining recent balanced tool units. System, previous checkpoints and status-only records do not satisfy the fresh-material minimum. Ordinary maintenance stops below the release target or at the explicit `maxPasses`, otherwise the public exact-route `compactionRetries + 1` (two passes when no setting exists); manual rest is scheduled through the durable inbox and runs after its tool batch completes. Tool results distinguish scheduled from completed.

For providers exposing public LLM summary configuration, one builder supplies system head, selected messages, tools and the final instruction to both planning and execution. It inherits exact-route public settings and accepts explicit summary overrides. Descending balanced prefix candidates must fit the summary route's complete hard input. Input overflow retries shorten the candidate within the configured limit. Unknown capacity still permits a provider attempt, including explicit `context_rest` at pre-step. If a budget-derived tail is unavailable, selection uses an explicit `retainTokens` or retains the latest complete unit. Without a known threshold, automatic pressure maintenance remains inactive. Custom providers without this configuration retain their `compactRegion` executor.

The summary directive records original explicit instructions and corrections separately from implementation choices, assumptions and completion status. A latest correction updates the attribution of older notes. This prevents an executor's decision to leave an action pending from becoming a claimed requester's prohibition.

The executor serializes per Session, captures the original surface/messages/header, rejects changes before commit, and compares the complete framed replacement under the frozen conversation basis. A replacement must reduce input; fixed shadow estimates cannot substitute for calibrated costs. Existing `compaction/start`, `compaction/summary`, replacement and `compaction/end` events preserve authoritative raw output, usage and source sequences. Errors close the transaction without claiming success. Started/prepared/committed/failed action records share the transaction id. A committed rewrite is still durable progress if later audit or summary work fails.

Deep rest writes the complete handoff and recovery paths without a summary-model call. Before measuring or opening the transaction it verifies that the selected contiguous source sequences still match. The handoff must be smaller under the operation basis. Its committed checkpoint replaces the selected history and the accepted batch removes duplicate scheduling text; original log records remain available for recovery. An earlier delegated ordinary replacement can satisfy normal rest, but cannot consume an explicit deep handoff.

Balanced proposal comparison prioritizes fresh-summary, then at least two old checkpoints separated only by context-care status, then a basic-compatible pressure fallback. Explicit rest requires fresh material or a merge; ordinary pressure does not lose its legal fallback to the fresh threshold. basic-prefix favors the largest range. target-prefix requires an explicit complete-checkpoint cost forecast and picks the smallest covering range, otherwise the greatest predicted saving. Actual summary shrink is checked independently. Durable no-useful decisions hash selected task messages, source sequences, effective prices and route policy; status/log-only growth cannot reset them. New task material or pricing can. Checkpoint coverage recursively expands summary shadow references and prune content references, excluding transaction markers; direct checkpoint parents and processing depth enter committed action records.

One maintenance controller owns occupancy across pruning, summary and deep rest per Session, while other sessions run independently. Contribution disposal cancels queued/running work and awaits settlement. The synchronous public summary-error waterfall remains delegated. A successful listener must produce a new selected-span replacement or recorded image offload, preserve outside nodes/messages and the header, and strictly reduce input under the frozen auxiliary prices. Replacements rebase both selected endpoints through content sources; a listener returning true without valid progress retains the original failure. Repair and actual-dispatch caps are optional explicit policy; local refusal does not consume dispatch count. Audit failures cannot mask the original model error and remain observable through journal flush.

LLM terminal normalization can remove the original failure class. After the public waterfall delegates without repair, the plugin adapts only canonical structured `IMAGE_OFFLOAD_REQUIRED` failures and only when the public `image/offload` projection is installed. It records the requested oldest selected image occurrences through that existing event. The same durable proof, fixed-price decrease and outside-stability checks govern the retry. Prepared calls rejected during local selection are released; listener, repair audit and error-close failures preserve the original model failure, leaving unmatched transactions observable if close fails.

## Session action display

The Host exposes a session-required, explicitly paginated read-only actions route with installed connection authentication and no-store responses. Its display projection excludes prompts, schemas and raw outputs. Admission shows latest conversation budget and declared/calibrated price components. Journal phases group by operation or summary transaction; transaction-to-operation mapping and replacement sequence identity avoid duplicate deep-rest entries. Existing checkpoint replacements recover commit facts only when the action audit is incomplete, with missing costs left unknown. Partial failures with audited durable replacements retain their failed/partial settlement.

The composer dock contributes numeric status and a locale-owned button. The button opens the current session's budget and maintenance records in a registered right-sidebar page; the record list is never rendered in the composer. A registration-owned observable supplies framework-generated hooks; view components own only page selection. Polling is scoped to retained session pages, refuses duplicate in-flight work, aborts released pages, and stops on contribution disposal. The distributed module factory is tested in an external Host's real SlotRegistry, SessionProvider and renderer under jsdom, including rendered DOM snapshot, paging, session switching and disposal. This does not modify or validate an installation in the existing live GUI.

## Overflow recovery

Provider `CONTEXT_WINDOW_EXCEEDED` can trigger recovery below the estimated soft limit. The failing call snapshot freezes its revision, used source sequences and prices. Recovery prunes, then forces a prefix with zero requested retention and no fresh-material gate, retaining the last complete unit. Retry requires a durable replacement after the failure revision that covers sources actually used and lowers complete reconstructed input under the failure basis. A local refusal also requires the reconstructed input to fit H; ready rechecks the actual retry. A committed prune can qualify when the following summary fails. Without qualifying progress, the original failure stays terminal. Normal output and idle reset bounded retry state.

The request journal owns its call identifiers and binds each Agent stream attempt to the plugin-observed request. Official rc.2 provides llm/stream, prepareCall and Agent stream events; no added Harness lifecycle events or meter methods are required. Auxiliary summaries enter the waterfall without consuming their prepared handle, then dispatch that same registration-bound handle after composition. Dispatched records mean prepared-stream handoff; adapter-internal network dispatch is not observed. Retry success cannot overwrite an older failed occurrence. Dispatch ordinals, rather than later settlement timestamps, select the previous same-purpose actual route. Request, prune, deep-rest and summary audit writes use explicit durability acknowledgement; unload removes listeners, drains writes and closes handles. Startup failure closes previously opened handles while preserving the original error.

## Request-only scoped prompts and output feedback

Rules match exact provider/model/purpose, with static, model-switch or output-pattern triggers. Model-switch uses the previous same-purpose actual dispatch, optionally initial bind. The plugin composes text against the public prepared config and dispatches through its registration-bound handle. Forwarded calls delegate once through official middleware; calls without a context-care owner pass through unchanged. Complete segment text is logged as metadata on the existing log-only `request/header`; it never joins retained surface, system history or summary selection. Preview and actual composition use the same selector, while ready prices the final request once.

Output-pattern vocabulary, thresholds, locale, text/statement/phrase/evidence limits, window size, cooldown, healthy rearm and delivery cap are explicit configuration. Maintained Markdown parsing excludes quotes, fences, inline code, HTML and image text; Intl.Segmenter supplies sentence/word segmentation. Literal matches merge overlaps longest first. N counts effective statements, K hit statements, H merged hits, F categories, J the largest same-category statement count and D=K/N. Source offsets and evidence are bounded. Arbitrary regex is unsupported. Over-limit outputs are unavailable, not healthy evidence.

Only successfully dispatched, complete committed conversation outputs enter exact-route bounded windows. Sequence deduplication prevents replay retriggers. New abnormal evidence can create one durable episode; completed-output cooldown and consecutive measurable healthy outputs govern rearm. Unavailable samples break the healthy sequence. Delivery is reserved as unknown before dispatch and bounded after a crash. Exhausted unknown pending episodes retain an audit record and can yield to a later eligible episode. Target rules explicitly permit cross-route carry; otherwise a route switch supersedes pending source feedback. This feedback waits for a natural request and does not create an extra turn or interrupt reasoning.

## Completion observation and restart

The completion Host owns observation state and a separate durable notice outbox. It parses authoritative block-end text and final committed visible text within `maxObservedChars`, excluding reasoning, tools, Markdown quotes/code and negation. It does not accumulate unbounded deltas. Writes serialize by session; pending durability precedes settlement. An occurrence identifies an attempt, while cooldown is scoped to session and producer source. A stale occurrence cannot settle or recover a newer pending record. Successful settlement retains a completed occurrence id; observation means affirmative output wording, not proof of actual task completion.

Successful observation publishes a route-scoped notice to verify delivery and validation scope on the next natural conversation request. Failed, interrupted and abandoned attempts recover matching pending without successful settlement. `notifications: false` disables delivery while preserving observations. Unknown reservations replay at most `maxDeliveries`. Only the newest eligible notice is selected; a natural dispatch supersedes older session notices so they cannot leak onto successive turns.

On the first natural request after restart, reconciliation uses the durable request journal's actual dispatch route and committed output sequences in order. A completed occurrence whose outbox write was missed finishes publication; other occurrences still respect source cooldown. A processed watermark prevents rescanning consumed sequences. Too-long filename keys are SHA-256 hashes of the session/source pair; legacy keys that could form JSON filenames remain unchanged. Store and publication failures keep their original errors. `contextCareCompletion.flush` is the observer ACK; Agent idle alone does not acknowledge that queue. Disposal stops listeners before draining and closing domains. Live output publication remains independent from the observer queue.

## Model experience and limits

Discrete status messages use append-only user role, retain numeric metadata for UI replay and notify only when visible grades/advice/outcome change. Numeric-only changes do not repeat model text. Necessary initial tool declarations and actual compaction change the input prefix and are not promised cache hits. High-load guidance asks for saved progress and maintenance; token statistics do not establish memory loss, cognitive deterioration, identity change or a task deadline.

Original S-forge references are checkout `6d612b0b201ee4179ef1f42269167d711ae510d0`, `kernel/nerv/magi/sages/token_counter.go:441` and `:494`, `sages/sage.go:356-391`, `prompts/core.go:19` and `coordinator/heartbeat_downtime.go`. The Codex reference is checkout `dbe2f6d52812a99ad929f6f342fa95d9da15b6ed`, `codex-rs/core/src/session/token_budget.rs` and `compact_token_budget.rs`. These are read-only design observations, not evidence for psychological claims or real-model effect sizes.

Legacy substring detectors can confuse using a phrase with discussing its implementation. Their notices use stated deadlines and known runtime facts for time planning, and current estimates and recovery paths for context planning; phrase hits cannot establish anxiety or hallucination. The Seraph label names the referenced reminder, not a connected clinical service. Loop handoffs preserve necessary verbatim details and accurate summaries with original-log recovery paths, rather than requiring every source text to be copied. The configured completed-output detector has structural exclusions but cannot establish intent either. No real-model A/B effect measurement has been performed. Summary quality depends on the provider; large artifact offload and long-term memory remain outside this package. Direct basic APIs and custom provider internal repair/hooks are not replaced or guaranteed to use plugin prices. Third-party middleware that changes input after this observer or creates independent calls is outside this observer's captured request; official rc.2 has no terminal adapter-dispatch event. Such middleware must preserve request association and supply its own budget enforcement for its changes.

## Validation

Standalone tests require no Harness installation and reject DSH package imports, dependency links and checkout paths in runtime artifacts. The explicit external `DSH_TEST_CHECKOUT` supplies real Cordis Loader YAML and public services. Source tests use its tsx ESM hook, file URLs and source aliases without relying on stale lib artifacts; built integration remains an explicit alternative. Every enabled fiber is awaited because Loader quiescence can include startup failure. Test-owned JSON roots and HTTP port-zero services are drained at teardown; the existing GUI and deployment are untouched.

The fixture maps the package root to the display companion and `/runtime` to the actual maintenance Host. It mounts request/completion/runtime/display rows together, disables display while checking live tools, sampling and HTTP queries, and checks route/tool removal only on runtime disposal. Adapters perform native AbortSignal fusion and verify cancellation identity; only LlmCallConfig fields reach prepareCall because its structured clone cannot preserve a native AbortSignal. Real Agent seed creation validates restored history before checking natural completion replay and missed publication. Captured requests and Session events validate system/prefix preservation, tool ordering, summary capacity and overflow, fixed shadows, actual calibration including a large one-shot prompt, failed-attempt isolation, bounded feedback and completion replay. The approximately 5.102 input-scale regression compacts once and adds ten small work steps with no repeated summary; invisible log additions leave frozen input price unchanged. Localized client tests and an independent client build verify the unchanged UI implementation. These tests mock the external LLM; they do not validate real-provider pricing accuracy or behavior improvement.
