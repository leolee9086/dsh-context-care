# 统一引擎迁移验收

## 实现与依赖

规则领域由 `@leolee9086/dsh-rule-engine@0.8.0` 实现。context-care 的请求服务持有一个 Engine，同步通知、请求改写、Workbench 文档和事件提醒都使用该实例。来源注册、声明编译、条件树和动作身份在引擎内共享；同步文本、基线补丁、顺序文本程序及事件交付保留各自的执行和提交策略。

context-care 的正式依赖精确指向 `0.8.0`。本轮验证使用 `pnpm pack` 生成的实际归档，经独立安装解析公开入口及声明；0.8.0 的 npm 发布与配套 context-care Git 标签属于后续发行步骤。思源来源开发依赖配套 context-care 发行归档，运行时通过 Cordis 服务接入。

| 请求与显示 | 模板、依赖、优先级/互斥、基线补丁、顺序文本、配对和预算 | 原生正文定位、带来源的消息构造、公开 tokenMeter 计量 |

## 能力超集

| 合同 | 统一实现与验证 |
| --- | --- |
| v1 同步 API | `applyRules`、`Engine.run` 和 `prepare` 保持同步；scope/order/词法 ID 排序、指定消费者与广播、未找到消费者和错误传播合同保留 |
| 酒馆文本 | 后一条读取前一条输出；查找宏三种模式、替换宏、捕获/具名捕获、trim、零宽、placement、编辑、深度及目标条件保留 |
| 基线补丁与顺序文本共存 | 一次性与增量补丁共用 `createBlockPatchPlan` 的优先级决议和阻塞恢复；`transform` 读取已裁决文本，正则与补丁共用 UTF-16 编辑内核；相互矛盾的跨阶段依赖在规范化时拒绝 |
| 公共条件 | provider/model/tool/参数/idle/数值/文本事实编译为共同节点；`when.condition`、块/事件 `match`、条目激活和接收范围共用布尔语法与求值，计数与事实 schema 作为叶节点组合 |
| 文本提交 | `Engine.prepare` 只准备提案；环境 ACK 后 `commit` 确认冷却和 surface 去重，失败不消费；来源、消费者、控制或实际引用能力变化会使旧提案失效 |
| 多动作与事件 | 每规则每轮只匹配/judge 一次；动作分别控制、依赖、冷却、候选、配额、冻结正文与回滚；赢家规则的全部适用动作保持可达 |
| 历史恢复 | 原生 handoff、消息 ID、签名和冻结正文优先；已消费配额、窗口与 sticky 事实保留；结果未知的副作用不自动重跑 |
| Worker 与预算 | 同步和异步规划执行同一文本程序；Host 等待可终止 Worker 时释放同步决策批次，完成后重验当前 token；原处理/启动/存储/队列预算保持 |
| 工作量与缓存 | 依赖 heap、区间补丁、工具配对、精确锚点和共享缓存保留；切面深度整批建立一次消息目录，避免每个子块扫描历史 |
| 真实下游 | 思源只提供原生块文本、连接、推送和接收资格，规则统一使用 `schemaVersion: 2`；解码、校验、来源缓存、增量失效、重试与撤回均在引擎 |

事件引擎执行共同声明。旧提醒消息中的 reminder/v1–v4 字段作为已发生的交付、窗口、sticky 与配额事实读取；文档输入只有共同声明，不再保留 v4 转换。读取已提交历史事实不引入另一套规则语法。

## 扩展合同

外部包通过 Engine 的 `extensions.registerCondition` 和 `registerAction` 提供命名空间 `ref`、正整数 `revision`、`paramsSchema` 与同步编译函数。声明使用 `{ kind: 'extension', ref, revision, params }`，可以嵌套进 `all`、`any`、`not`、`when.condition` 和条目激活。编译产物再次经过共同规则校验，再交给相同 Worker。

每个动作扩展产生一个核心动作。调用方的 ID、阶段、依赖、默认开关、去重和冷却身份保留；实际副作用由版本化执行器端口承担。扩展编译器不拥有第二套状态或交付账本。检测器继续支持参数/状态/证据 schema、流状态和可终止执行。自定义事件通过原生事件目录映射，事实由 Host 读取其原生锚点。

注册/替换/释放按贡献所有者处理，旧释放句柄不删除新贡献。编译检查记录实际引用的能力；扩展卸载会撤销依赖它的计划、排队动作与事件候选，无关扩展保留已有候选。运行中的执行器被卸载时取消对应端口，保留可能已经发生的外部效果为未知结果。新的事务、坐标或效果语义通过扩展共同核心合同接入。

独立测试包覆盖条件与内建条件组合、动作和执行器、文档来源、原生事件映射、控制与冷却、ACK 失败、结果未知、持久恢复、队列/运行中卸载、旧句柄、来源快照及映射恢复。Host 的能力目录通过现有 catalog/inspect 接口提供参数 schema 与版本。

## 验证方式

引擎使用原有严格 TypeScript 与 lint 配置，未放宽编译选项。插件使用标准 tsc、Node、浏览器打包器和实际安装包的 `exports`/`types`，没有引擎源码解析替换。

```sh
# 引擎
pnpm check
pnpm pack --pack-destination artifacts

# context-care
pnpm check
pnpm sync:events:check
pnpm test
pnpm build
```

真实 Host 和 UI 由执行者设置 `DSH_TEST_CHECKOUT` 指向 Harness 源码库，再运行：

```sh
pnpm test:integration:source
pnpm test:client:source
```

这些检查使用真实 Context、Loader、Session、日志和公开服务。独立行为测试在引擎端口下运行，来源适配测试只验证原生文本与服务契约；解码、单条诊断、增量生命周期和编译复用在引擎独立测试。独立插件归档消费者检查公开入口、客户端工厂、嵌套请求写入和真实 Worker。部署 GUI 与源码验证分别对应各自版本。
