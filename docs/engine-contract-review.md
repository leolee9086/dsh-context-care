# 引擎端口、转发与生成契约复核

本轮同时复核三项问题。引擎 `@leolee9086/dsh-rule-engine@0.7.0` 已正式发布至 npm，插件精确依赖和锁文件已更新；插件尚未发行新版本。

## 结论与实现

| 问题 | 核查结果 | 修复 |
| --- | --- | --- |
| `createEventRuntime` 用空函数掩盖环境漏接 | 成立。状态和容量可能得到空 ACK，观察、错误与政策重置边界可能静默失效 | `saveCapacity`、`changed`、`report`、`sinceSeq` 必填；独立模式另要求 `save`，原生 `sessionAuthoritative: true` 允许省略旧状态写入器。TS 联合类型与创建时函数校验同时约束接入 |
| 插件转发引擎符号以及转发指向不存在的符号 | 转发成立；针对实际正式 `0.6.0` 审计的 59 个模块、210 个值/类型转发符号全部存在，未复现缺符号 | 删除纯转发文件、混合模块转发和二层兼容入口；生产、测试、动态导入及 JSDoc 直接引用库公共入口。保留实际原生环境封装 |
| 跨库 `EventFieldShape` 双真源 | 成立。引擎 selector 手写，插件生成器另生成一份；两者当时结构等价但独立维护 | 将原生成器结构模板移入引擎生成脚本，删除手写定义。引擎各调用与公共类型导出都指向生成模块；插件生成器、生成目录及 selector 直接导入这一公共类型 |

引擎唯一类型定义位于 `src/generated/event-field-shape.ts`，由 `scripts/generate-event-field-shape.mjs` 生成。环境目录仍从固定 DSH 发布 schema 生成原生事件名和 payload 数据，环境不再声明或转发第二个 `EventFieldShape`。插件的 Cordis `Config`、品牌消息、原生事件转换和 I/O 服务属于真实环境声明与适配。

保留合法的空初始数据：`entries` 可为空，独立环境没有内置原生事件目录时 `catalog` 可省略。没有政策重置的独立环境须显式传 `sinceSeq: () => -1`。领域测试用显式内存环境提供所需端口，生产构造函数不提供测试缺省。

## 防回退门禁

- 引擎构建先运行 `check:generated`，生成产物与唯一模板不一致即失败。
- 引擎 `check:types` 以生产严格 TS 配置编译公共声明正反例：独立模式不能漏写入器，原生模式允许省略旧写入器，其它四端口始终必填。
- 插件依赖门禁检查源码和构建输出：每个静态引擎值/类型导入必须存在，不得直接或间接转发引擎符号，不得重新声明 `EventFieldShape`。
- 现有 schema、选择器、事件及恢复测试继续使用相同领域实现，通过普通包解析调用，不设置引擎源码 alias。
