# 2026-09-24 改写卡片渲染退役修复与实机验收

## 目标与背景

修 `D:/dev/dsh-context-care` 的**请求改写审计卡片**：会话流里每条被改写的助手消息下面，应该出现一张"请求改写"卡片，让人看得出这条输出在发请求前被动过。同时处理 `D:/dev/dsh-fetch-router` 的请求改写与传输异常诊断。

机制回顾（本轮确认过的）：
- 改写发生在**请求层**（fetch-router 的 `requestRewrite` 服务），执行者是 context-care 注册的改写器。
- 改写事实**不进会话日志**（自定义事件类型会被 DSH 读侧校验拒载），走**旁路流水账 journal**：落在块索引插件的属性表（`ctx.get('sessionBlockQuery')` 的 `putAttribute`），表名 `attribute`，namespace `context-care`，name `request-rewrite`；属性表不在就只在进程内。
- 客户端拿不到事件 seq，所以**用内容哈希配对**：host 侧算被改写前文本的 FNV-1a 32 位哈希，客户端对会话流里助手消息的文本块算同一个哈希，相等就认为"这条被改过"。
- 客户端每 2 秒轮询 host 的裸路由 `/context-care/rewrite-journal`（同源 fetch 自动带 Cookie），把记录塞进一个 observable，通过**注册级 hooks** 注入给卡片组件。

## 已完成（本轮，按时间顺序）

### 1. 根因：卡片渲染器被插槽边界"退役"（abdicate）

**现象**：卡片从来不显示；但 journal 里有记录、路由也在。

**证据**：`cordis_inspect_query` client `Slots.listSubTree`（root=`conversation.chat.node`）返回的 occupants 里，`request-rewrite` 是**唯一** `active: false` 的（其余全是 true）。

**机制**（读 DSH 只读源码得到）：
- `packages/client/ui-slots/src/index.ts`：`LiveSlotOccupant.active` 的注释是 "Whether the renderer currently selects this entry"；计算处是 `active: active.has(entry)`，集合来自 `entriesOfSlot(name)`。
- `entriesOfSlot()` 里第一句过滤：`if (this.abdicated.has(entry)) continue`。
- `reportEntryError(key, entry, error, { abdicate })` 把 entry 加进 `abdicated`（WeakSet）。
- `packages/client/ui-renderer/src/client/scoped-slots.tsx` 里 keyed slot 的 entry 渲染边界：`host.reportEntryError(slotKey, entry, error, { abdicate: spec.kind !== 'chain' })` —— **keyed 槽崩溃即永久退役**。

**抛错的具体原因**：`RewriteNodeView` 调用注册级 hooks 注入的 `useRewriteRecords()` 时**没传 selector**。
- `bindInjectSources` → `observableHook(source)` → `bindSnapshotSelector(w)`（`packages/client/ui-renderer/src/client/bind.ts`）：
  ```js
  return function useSelector(sel, eq) {
    return useSyncExternalStoreWithSelector(subscribe, getSnapshot, undefined, sel, eq)
  }
  ```
  `sel` 是必需参数；不传就是 `undefined`，shim 内部调用 `selector(nextSnapshot)` → TypeError → 渲染崩溃 → 退役。

**修法**（`src/rewrite-view.js`）：
```js
const table = useRewriteRecords(value => value)   // 选择器是必需参数
```

**验证**：同一条 inspect 查询，`request-rewrite` 从 `active:false` 变 `active:true`。

### 4. 卡片内容改进（**已改完、已跑测试、尚未提交**）

哥哥指出：卡片"对生效规则的展示过于粗略，没有什么实际价值"——只报一个规则 id 和字符数（`probe-request-rewrite · 5937 → 5869`），看不出改了什么，同一 pattern 还重复出现。

改动：
- `src/rewrite-journal.js`：新增 `SNIPPET_LIMIT = 80`、`diffSnippet(before, after)`（掐公共前后缀，中间即真正动过的地方）、`clip(text)`（超长截断加 `…`）；`changedBlocks()` 的返回项加 `removed`/`added`；`record()` 的 value 里存这两个字段。
- `src/request-rewrite.js`：`journal.record({...})` 传 `removed: block.removed, added: block.added`。
- `src/rewrite-view.js`：新增 `oneLine(text)`（换行换成 `↵` 保持单行）、`snippetRows(hit)`（`− 去掉的` / `+ 换成的` 两行，纯插入或纯删除时只画有内容的一行）；`RewriteNodeView` 的 children 里展开 `...snippetRows(hit)`。
- `src/index.js`：**删掉**临时探针规则 `probe-request-rewrite`（原注释写着"验证完删掉这一段"）。删掉的原因还有一个：`memoryNoticeRules` 里的规则**全是 `placement: ["user"]` 的提醒规则**，根本不产生请求改写，所以卡片以后只在**循环清理**时出现——那才是有意义的场景。
- `test/rewrite-journal.test.js`：属性表测试数据补**顶层** `sessionId`。去重键是 `row.value?.sessionId + ':' + row.hash`，而 `list()` 里 `value: { ...item.value, sessionId: item.sessionId }` 会用顶层值覆盖 value 里的值；测试数据只有 value 那份，于是被覆盖成 `undefined`，两条同哈希记录被当成不同会话 → 断言 3 !== 2 失败。
- `test/rewrite-view.test.js`：`renderNode` 的 mock 改成严格契约（`useRewriteRecords: selector => { if (typeof selector !== 'function') throw ...; return selector(records) }`），并加片段断言。
